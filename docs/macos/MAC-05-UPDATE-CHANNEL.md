# MAC-05 — общий канал обновлений Windows и macOS

## Протокол

Общий Go-сервис запрашивает `/repos/pembrock/find-a-note/releases/latest`.
Проверки запускаются в production в фоне при старте и раз в час. Диалог
также запускает ручную проверку. Сервис исключает draft и prerelease,
принимает тег `vX.Y.Z` и использует только загруженные assets с положительным
размером. Дубликат имени считается ошибкой. HTTP 404 означает отсутствие
стабильного выпуска. Прочие ошибки API и сети показываются в диалоге.
URL для скачивания строится из фиксированного репозитория, проверенной
версии и имени файла. Переадресации ограничены известными HTTPS-хостами GitHub.
[GitHub Releases API](https://docs.github.com/en/rest/releases/releases)

Схема 1 содержит `schema`, `product` (обязательно `find-a-note`),
`version`, `notes` и `packages`. Каждый пакет содержит `os`, `arch`,
`kind`, `name`, `size` (байты), `sha256` (64 строчных hex-символа) и
`method`. Допустимы 1–16 пакетов размером до 256 MiB. Комбинации
`os/arch/kind` и имена без учёта регистра уникальны.

Канонизация — UTF‑8 байты `json.Marshal` фиксированных Go-структур, с
порядком полей и массивом пакетов как в manifest, без отступов, BOM и
заключительного перевода строки. Размер manifest до 32 KiB. Отдельный
`update-manifest.sig` содержит ровно 64 сырых байта Ed25519. Оба клиента
проверяют подпись оригинальных байтов встроенным публичным ключом, затем
декодируют и сравнивают результат повторной канонизации побайтово.
Поля вне схемы, дубликаты полей и иное представление JSON отклоняются.
Подписанная версия обязана совпасть с тегом. Сервис отклоняет равную или
меньшую версию, сравнивая компоненты `X.Y.Z` как числа uint16.
Windows helper повторяет проверку версии, подписи, типа и целостности
пакета перед заменой. Он по-прежнему проверяет EXE, извлечённый NSIS,
по подписанной записи Portable.

`notes` — подписанный UTF‑8 текст до 4096 байт. Двуязычный текст оформляется
как `English\n\n…\n\nРусский\n\n…`. Локализованный интерфейс выбирает
секцию по активному языку. Обычная строка отображается целиком. Код
Go передаёт старым клиентам те же байты, а публичный 0.2.2 выпущен
до двуязычного интерфейса.

## Единый релиз

Одна версия `X.Y.Z` в Windows и macOS и один стабильный тег `vX.Y.Z`.

| Артефакт | Запись / метод |
| --- | --- |
| `Find-a-Note-X.Y.Z-Windows-Setup.exe` | `windows/amd64/installer`, `nsis-stage-v1` |
| `Find-a-Note-X.Y.Z-Windows-Portable.exe` | `windows/amd64/portable`, `replace-exe` |
| `Find-a-Note-X.Y.Z-macOS-arm64.dmg` | `darwin/arm64/dmg`, `manual-dmg` |
| `update-manifest.json`, `update-manifest.sig` | Канонический manifest и подпись |
| `SHA256SUMS.txt` | Суммы трёх пакетов для ручной сверки |

Windows выбирает установочный тип по EXE и записи per-user NSIS. Для
Installer обязательна также корректная запись Portable. Apple Silicon
требует точную тройку Darwin, arm64, DMG, ожидаемое имя и метод.
У всех выбранных пакетов сначала сверяется объявленный GitHub размер.
При чтении байтов сервис сверяет фактический размер и SHA-256.

[Пример общего manifest](MAC-05-MANIFEST-EXAMPLE.json) содержит условную
версию и тестовые данные. Это форматированный пример для чтения.

## Совместимость Windows

`scripts/test-update-legacy.sh` извлекает Go-код updater из публичных
тегов `v0.2.2` (`a56e6d6`) и `v0.3.0` (`852a697`) и запускает
один интеграционный тест на обоих снимках. Реальный `GitHub` parser получает
ответы локального HTTP-сервера, проверяет подпись временным публичным
ключом, загружает и проверяет выбранные байты. Обе версии выбирают Setup и
Portable отдельно, пропускают запись DMG, отвергают неподходящую
архитектуру и неверную подпись, сохраняют текст notes. Тест отдельно
доказывает отказ при неизвестном поле даже с корректной тестовой подписью.
Поэтому расширение меняет только значения в массиве `packages`. Launcher
в тесте вызывает исторический селектор и записывает результат вместо
запуска EXE. Реестр, NSIS, rollback и отображение старых Windows UI в
нативной среде требуют отдельной проверки.

## Ручное обновление macOS

Диалог показывает доступную и установленную версии, подписанные заметки и
ошибки. После «Проверить DMG» общий сервис потоково сверяет размер и хеш
пакета с manifest. Только при успехе диалог показывает проверенный SHA-256
и кнопку официального GitHub Release для подписанной версии. Браузер
скачивает пользовательскую копию и сохраняет штатный quarantine. Перед
открытием скачанного файла нужно сверить его повторно, поскольку браузер
выполняет отдельный запрос:

```sh
shasum -a 256 "$HOME/Downloads/Find-a-Note-X.Y.Z-macOS-arm64.dmg"
```

Если сумма совпала, закройте Find a Note и замените приложение из образа.
Gatekeeper применяет системную политику к загруженной копии. У текущего DMG
подпись ad hoc. Подробности установки и зафиксированная блокировка —
в [MAC-04A](MAC-04A-DMG-DESIGN.md).

## Подготовка первого общего релиза

1. Сведите Windows и macOS в один просмотренный коммит общего исходного
   дерева. Выберите следующую версию один раз в `wails.json`. Проверьте оба
   Windows-формата и macOS на их нативных хостах.
2. Соберите Windows по `scripts/build-release.ps1` без подписи на этом шаге.
   Соберите macOS по [MAC-04A](MAC-04A-DMG-DESIGN.md). На доверенной Windows
   машине заведите отдельный каталог для трёх финальных пакетов. Перенесите
   туда DMG, сравните SHA-256 с суммой, полученной на Mac, и проверьте
   совпадение версий всех пакетов.
3. Из корня общего checkout выполните команду ниже. `$signingKey` указывает
   на уже существующий внешний ключ в доверенной Windows среде. Signer
   отклоняет ключ, который не соответствует встроенному публичному ключу,
   и проверяет подпись перед записью. `$stage` — каталог трёх пакетов,
   `$notesFile` — UTF-8 notes, `$version` — строка из `wails.json`.

   ```powershell
   go run ./cmd/update-manifest -macos -key $signingKey -version $version -dir $stage -notes $notesFile
   if ($LASTEXITCODE -ne 0) { throw 'Signing failed' }

   $files = @(
       "Find-a-Note-$version-Windows-Setup.exe"
       "Find-a-Note-$version-Windows-Portable.exe"
       "Find-a-Note-$version-macOS-arm64.dmg"
   )
   $checksums = foreach ($name in $files) {
       $digest = (Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $stage $name)).Hash
       "$($digest.ToLowerInvariant())  $name"
   }
   $checksums | Set-Content -Encoding ascii (Join-Path $stage 'SHA256SUMS.txt')
   ```

4. Перед публикацией проверьте подписанные байты и полный набор assets в
   изолированной среде, затем подтвердите нативные сценарии старых
   Windows-клиентов и ручное обновление macOS из скачанного DMG. После
   разрешения владельца один стабильный релиз должен получить все шесть
   файлов и соответствующие исходники. Релиз с одним OS-пакетом создаст
   неполное предложение для клиентов, читающих `latest`.

## Ограничения и MAC-06

MAC-05 использует существующий production trust anchor. Локальные проверки
производят временные Ed25519 ключи в памяти. Для подключения MAC-06 требуется
отдельное разрешение владельца и решение по Gatekeeper, безопасному
транзакционному обновлению bundle, подтверждению старта и откату с
сохранением WKWebView. Ручная загрузка MAC-05 оставляет применение
обновления пользователю.

## Проверки

Результаты записаны в `artifacts/mac-05/`. Команды для повторения после
сборки frontend:

```sh
GOTOOLCHAIN=go1.26.11 ./scripts/test-update-legacy.sh
GOTOOLCHAIN=go1.26.11 go test ./...
GOTOOLCHAIN=go1.26.11 go vet ./...
GOTOOLCHAIN=go1.26.11 go test -race -count=2 ./...
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 GOTOOLCHAIN=go1.26.11 \
  go build -tags desktop,production,wv2runtime.embed -o /tmp/find-a-note.exe .
```

CoreMIDI проверялся отдельно с fixture из [MAC-02A](MAC-02A-LIFECYCLE.md),
10 прогонов и ещё два прогона с race detector. UI проверялся с
`PLAYWRIGHT_BROWSER=chromium` и `PLAYWRIGHT_BROWSER=webkit` через
`npm run test:ui` из `frontend/`.

| Проверка | Результат |
| --- | --- |
| Старые Windows Go-клиенты v0.2.2 и v0.3.0 | **PASS**. Реальный parser и Ed25519, оба типа пакетов, несовместимая архитектура, неизвестное поле, неверная подпись. |
| Заметки в исторических интерфейсах | **PASS** в локальном Chromium с исходными React-компонентами обоих тегов. 0.2.2 показывает полный текст, 0.3.0 переключает секции RU/EN. |
| macOS discovery, выбор и целостность | **PASS**. Локальный GitHub-like сервер, временные ключи, неверные размер/хеш и повреждённый manifest, неверная версия, downgrade, ошибки API и offline. Apple Silicon launcher отказывается запускать установку. |
| Frontend | **PASS**. Production build, 13/13 unit, Chromium 63/63 и WebKit 63/63, включая новый ручной диалог и существующие Windows-сценарии. |
| Go и CoreMIDI | **PASS**. Go test, vet, race, нативный lifecycle fixture и 10 прогонов с виртуальным источником. |
| Сборки | **PASS**. Production arm64 DMG с проверкой подписи, embedded ресурсов и контрольных сумм. Кросс-компиляция Windows amd64 с production tags дала PE32+ EXE. |
| Windows native, NSIS, реальный опубликованный общий релиз | **NOT TESTED**. Windows-хост и опубликованный общий релиз отсутствовали. Production подпись совместного manifest оставлена доверенной Windows машине. |
