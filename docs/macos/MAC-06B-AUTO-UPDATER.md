# MAC-06B · Установка обновлений на Apple Silicon

## Канал обновлений

MAC-06B использует общий `internal/update.Service`, GitHub Release и
закреплённый публичный ключ Ed25519. Manifest schema 1 и пакет
`darwin/arm64/dmg` с методом `manual-dmg` совместимы с MAC-05 и старыми
Windows-клиентами. Метод в manifest сохранён для совместимости. Решение о
режиме установки принимает локальный клиент. Windows использует прежние
Setup и Portable. Опубликованная 0.4.0 ещё использует старый ручной клиент.
Первую версию с MAC-06B нужно установить обычным способом из DMG.

На поддерживаемом пути интерфейс предлагает загрузку с прогрессом и отменой,
затем отдельное подтверждение установки и перезапуска. Общий сервис
проверяет подпись, стабильную возрастающую версию, точное имя, размер
и SHA-256. В неподдерживаемом месте диалог предлагает проверенный ручной
DMG. Примеры таких мест — read-only том, App Translocation, путь через
симлинк, каталог с недостаточными правами либо каталог другого пользователя.
Повышение привилегий не используется. Путь определяется по запущенному
исполняемому файлу, поэтому доступны и подходящие пользовательские каталоги
за пределами `/Applications`.

## Подготовка и установка

1. После подтверждения Go повторно проверяет подписанный manifest и пакет.
   Есть предварительная проверка свободного места. DMG копируется в
   приватный каталог транзакции рядом с текущей .app на том же томе.
2. Go HTTP-загрузчик сам не назначает quarantine. До монтирования updater
   назначает DMG новый атрибут quarantine. Системное разрешение предыдущей
   .app не копируется. `hdiutil verify` проверяет образ, а `hdiutil attach`
   монтирует его только для чтения, без открытия Finder.
3. В образе ожидается `Find a Note.app`. Проверяются структура, отсутствие
   симлинков, пакетный тип APPL, идентификатор `io.github.pembrock.findanote`,
   обе версии Info.plist, arm64 Mach-O и целостность подписи через
   `codesign --verify --deep --strict`. `ditto` сохраняет метаданные.
   Updater повторяет проверку и требует, чтобы копия унаследовала quarantine.
4. Приложение атомарно записывает журнал и запускает отдельную копию своего
   Go-исполняемого файла в режиме helper. Helper наследует блокировку
   транзакции. Перед заменой он берёт эксклюзивную блокировку, которую
   запущенные экземпляры приложения удерживают в совместном режиме.
   После проверки обеих .app helper выполняет `renameatx_np(RENAME_SWAP)`.
   Новая .app занимает исходный путь, а прежняя остаётся в каталоге
   транзакции с исходными байтами и метаданными. При неподдерживаемом обмене
   прежний путь сохраняется.

## Запуск, Gatekeeper и откат

Helper вызывает Launch Services через `open`. Успех этой команды означает
приём запроса. Готовность подтверждает React после инициализации, используя
существующий вызов `FrontendReady`. Для подтверждения нужны точный хеш
запущенного executable и проверенная установленная копия. Учитывается запуск
через App Translocation. После записи маркера helper очищает транзакцию.
Отдельное приложение с идентичным подписанным executable, запущенное из
App Translocation в тот же момент, не различается по исходному пути.

Если подтверждение задерживается, helper показывает инструкцию, повторный
запуск и кнопку восстановления. Системное сообщение может потребовать
**Системные настройки → Конфиденциальность и безопасность → Всё равно открыть**
для новой Find a Note. Helper не меняет политику, не удаляет quarantine и
не использует результат `spctl` для решения об откате. Ожидание разрешения
без срока. «Позже» оставляет backup и журнал. При дальнейшем успешном
запуске приложение принимает транзакцию и запускает очистку. Диалог Wails
локализован по языку приложения. Диалог helper использует язык macOS.
[Открытие приложений в macOS](https://support.apple.com/en-us/102445) ·
[Проверка загрузки и App Translocation](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution)

Подтверждённая ошибка инициализации от Wails записывает отдельный маркер
и запускает откат после завершения процесса. При отказе до этой точки
пользователь может явно выбрать **Восстановить**. Helper сохраняет намерение
в журнале, повторно проверяет обе версии и обменивает их только после
выхода приложения. Прежняя версия запускается через Launch Services и
показывает сообщение о восстановлении. Версия, отклонённая при откате,
исключается из последующих предложений. Следующую, более новую версию
клиент может предложить обычным путём. WKWebView, bundle ID и origin Wails
остаются прежними.

## Восстановление после прерывания

У атомарного обмена два наблюдаемых состояния. До обмена на целевом пути
находится старая версия. После обмена на целевом пути находится новая,
а старая находится в `payload.app` под каталогом транзакции. Helper сверяет
состояние по обеим версиям и хешам. Предыдущая версия после перезапуска
может завершить прерванную подготовку отменой кандидата, новая завершает
успешную транзакцию по готовности. После прерывания уже начатого отката
старый bundle остаётся по штатному пути, а маркер восстановления позволяет
завершить его учёт. Если процесс завершился до записи журнала, скрытый
каталог подготовки может остаться сиротой.

Если helper был прерван после обмена и новый bundle не удаётся запустить,
восстановление можно продолжить отдельно. В
`~/Library/Application Support/io.github.pembrock.findanote.updates/transaction.json`
поле `Stage` указывает на скрытый каталог рядом с ожидаемой `Target`.
Из Терминала, под тем же пользователем, запустите сохранённый executable
`"<путь из Stage>/helper" --find-a-note-mac-recover`. Helper проверяет свою
позицию, точные версии, подписи и взаимное расположение путей. Из его
диалога доступно восстановление. Параллельный helper блокируется. Если
состояние диска не распознано, helper сохраняет backup и сообщает об ошибке.
Удалять каталоги при таком сбое до проверки копий не следует.

## Проверки

macOS 27.2.1 arm64, Wails 2.17.0, Go 1.26.11. Нативные сценарии
используют тестовые Wails-копии с отдельными bundle ID, профиль
каждой пары и тестовый manifest, подписанный временным ключом.
Код тестового стенда и журналы находятся в `artifacts/mac-06b/`.
Стенд поставляет артефакты общему Service через локальный провайдер;
разбор HTTP GitHub отдельно покрыт репозиторными тестами loopback.

| Сценарий | Результат |
| --- | --- |
| Frontend build и unit | **PASS**, 13/13. |

| WebKit | **PASS**, 63/63 в повторе. Первый прогон 62/63 из-за таймаута клика в тесте настроек. |
| Подтверждение обновления macOS RU/EN | **PASS**, отдельный сценарий прошёл в Chromium и WebKit. |
| Go test, vet, race | **PASS**. |
