# MAC-06 · Обновление Find a Note на Apple Silicon

## Решение

Для текущего распространения с ad hoc подписью оставлен ручной сценарий
MAC-05. На macOS 27.2.1 (26B131) системная оценка изолированной копии 0.4.0
с тестовым quarantine отклонила запуск. Разрешение на запуск предыдущей
версии нельзя считать разрешением для следующей. Обновление из интерфейса
позволяет найти релиз, проверить пакет и перейти к его скачиванию. В диалоге
RU/EN объяснены первый запуск, системное предупреждение и необходимость
сохранить предыдущую версию до проверки новой.

Подпись Ed25519 удостоверяет манифест проекта, а ad hoc codesigning
проверяет целостность bundle. Для штатного доверия Gatekeeper на внешнем
канале Apple предусматривает Developer ID и нотариальное заверение. Системная
политика может требовать отдельное решение пользователя либо запретить
открытие. Загрузка без штатных метаданных происхождения и прямой запуск
исполняемого файла не подтверждают прохождение этой проверки.
[Безопасный запуск приложений](https://support.apple.com/en-us/102445) ·
[Developer ID](https://developer.apple.com/developer-id/) ·
[Проверка дистрибутива](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution)

## Общий канал

`UpdateBridge` связывает Wails и React с общим `internal/update.Service`.
Провайдер получает стабильный GitHub Release. Сервис сверяет версию,
проверяет Ed25519 по исходным каноническим байтам manifest schema 1 и
выбирает запись через платформенный launcher. На Apple Silicon ожидаются
`darwin/arm64/dmg`, `manual-dmg` и имя
`Find-a-Note-X.Y.Z-macOS-arm64.dmg`. Потоковая проверка сверяет размер и
SHA-256, сообщает прогресс и допускает отмену. Пакет при этой проверке
не сохраняется и не монтируется. Кнопка открывает страницу подписанной
версии, а отдельную копию браузера нужно проверить повторно.
Windows использует тот же протокол с отдельными записями Setup и Portable.
Закреплённый ключ и схема остаются прежними.
[MAC-05](MAC-05-UPDATE-CHANNEL.md)

## Ручная установка и восстановление

1. В диалоге обновления нажмите «Проверить DMG». После успешной проверки
   откройте страницу релиза и скачайте DMG для Apple Silicon.
2. Сверьте сумму скачанной копии с SHA-256 из диалога:
   `shasum -a 256 "$HOME/Downloads/Find-a-Note-X.Y.Z-macOS-arm64.dmg"`.
   При несовпадении прекратите установку. Для диагностики образа можно
   дополнительно выполнить `hdiutil verify`.
3. Завершите Find a Note. Сохраните предыдущий bundle в отдельном месте.
   Откройте образ в Finder и скопируйте новую версию в тот же каталог
   и под тем же именем. Для обычной установки используйте
   `/Applications` или доступный пользователю `~/Applications`.
   В произвольном каталоге нужна возможность заменить bundle штатными
   средствами Finder. Если прав нет, используйте разрешённый каталог.
   Из read-only DMG или App Translocation сначала установите приложение
   через Finder в постоянное место.
4. Отключите образ и откройте установленную копию через Finder. При
   предупреждении macOS после проверки источника и суммы пользователь
   может оценить доступное системное действие «Всё равно открыть».
   При запрете политикой прекратите установку. Не удаляйте quarantine
   и не меняйте настройки Gatekeeper или SIP.
5. Сверьте версию в «О программе», откройте тренировку и проверьте язык,
   октавы, подписи, звук, MIDI-устройство и калибровку. При ошибке завершите
   новую версию и верните сохранённый bundle на прежнее место через Finder.
   Каталоги данных WKWebView оставьте на месте. Сохранение профиля между
   версиями предполагает тот же bundle ID `io.github.pembrock.findanote`,
   тот же origin и совместимые значения `sonari.*`.

Для повторения проверки используйте отдельного пользователя macOS или VM,
изолированную копию и временный подписанный GitHub-подобный feed. Для
диагностики можно независимо проверить `codesign --verify --deep --strict`,
`xattr -p com.apple.quarantine`, `spctl --assess --type execute --verbose=4`
и `syspolicy_check distribution`. Сравните фактический результат первого и
повторного открытия. Установленную рабочую копию и профиль в тест не включайте.

## Условия для транзакционного обновления

Для будущего релиза нужна подтверждённая возможность штатного запуска
нового bundle с сохранённым quarantine. Если модель распространения
изменится, проверить доверие к дистрибутиву на чистой системе до реализации
замены. Helper должен работать только с установленным bundle в доступном
каталоге и с транзакцией на том же томе. Перед изменением цели нужны проверка
свободного места, защита от симлинков и подмены путей, проверка подписанных
размера и хеша, структуры образа, bundle ID, версии, архитектуры и системной
подписи. Для DMG, translocation, недоступного каталога или неподходящего тома
должен оставаться ручной сценарий.

После подтверждения пользователя helper должен дождаться завершения старого
процесса и сохранить проверенную резервную копию. Журнал транзакции должен
позволять завершить либо отменить замену после сбоя самого helper. Запуск
через Launch Services должен пройти системную оценку. Только подтверждение
готовности конкретного нового экземпляра после инициализации окна и frontend
может завершить транзакцию. На Windows такой сигнал идёт через
`UpdateBridge.FrontendReady`. При отказе, падении или таймауте helper должен
восстановить предыдущий bundle и сохранить профиль. В MAC-06 автоматическая
транзакция, сигнал готовности Darwin и автоматический откат отсутствуют.
