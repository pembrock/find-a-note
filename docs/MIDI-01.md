# MIDI-01: физический MIDI-ввод

## Запуск и проверка Yamaha P-45

1. Включите пианино и подключите USB TO HOST к компьютеру USB-кабелем передачи данных. Дождитесь обнаружения Windows. Отключите транспонирование и смещение октавы на пианино.
2. Запустите `build/bin/Find a Note.exe` или Windows Portable EXE.
3. Нажмите область устройства внизу слева. Нажмите «Обновить список», выберите имя, предоставленное Windows: оно может отличаться от «Yamaha P-45», например «Digital Piano».
4. Должен появиться зелёный индикатор и «Подключено (MIDI)». Ошибка открытия выводится в меню; если порт занят, закройте другое MIDI-приложение и нажмите «Повторить подключение».
5. В «Первых нотах» сыграйте текущую ноту C4–G4 (среднее до = MIDI 60). Проверьте один зачёт и зелёную клавишу. Сыграйте другую ноту — должна добавиться одна ошибка, правильная нота не меняется.
6. Удержите неправильную клавишу больше секунды: ошибки не должны накапливаться. Отпустите и нажмите снова: добавится новая ошибка. При верном ответе повторные нажатия во время результата не должны давать дополнительный зачёт.
7. Скройте буквенное и русское обозначения: верный MIDI-ответ раскрывает названия на 1200 мс. В своей тренировке проверьте «Точную клавишу» и «Любую октаву».
8. В меню устройства отображается последний полученный MIDI Note On: нота, номер MIDI, канал 1–16, velocity. Note Off и Note On с velocity 0 не засчитываются как ответы.
9. Отключите USB, дождитесь обновления состояния (опрос раз в 2 секунды), проверьте виртуальные клавиши. Подключите кабель и подождите несколько секунд: ранее выбранное пианино должно подключиться автоматически, если найдено одно точное совпадение. Проверьте новое нажатие. При неоднозначности выберите вход вручную; кнопка «Повторить подключение» остаётся доступной.
10. Закройте Find a Note с подключённым пианино, запустите снова. Последний выбранный вход подключается автоматически только при единственном точном совпадении идентичности. Если одинаковых входов несколько, выберите вручную.

«Виртуальная клавиатура» в меню закрывает физический MIDI-порт и сохраняет выбор виртуального ввода. Панель пианино остаётся доступной при подключённом MIDI; её видимость и диапазон тренировки не меняются.

## Реализация

Go вызывает системные `midiInGetNumDevs`, `midiInGetDevCapsW`, `midiInOpen`, `midiInStart`, `midiInStop`, `midiInReset`, `midiInClose` из `winmm.dll`. CGO выключен. Дополнительные DLL, пакеты MIDI и драйверы не устанавливаются. Используется уже имевшийся в проекте `golang.org/x/sys/windows` для загрузки системной DLL; он отмечен прямой зависимостью.

WinMM callback только складывает сообщения в ограниченную очередь. Один Go-обработчик последовательно управляет портами, held-состоянием по каналу/ноте и публикацией Wails-событий. Из callback не вызываются мультимедийные функции: это ограничение [MidiInProc](https://learn.microsoft.com/en-us/previous-versions/dd798460(v=vs.85)).

Каждое соединение имеет свой номер сессии. Сначала инвалидируется старый ввод, затем закрывается порт; старые callback и Wails-события не поступают в проверку. Переполнение очереди переводит соединение в явную ошибку, чтобы потерянный Note Off не оставлял незаметно удерживаемую ноту. При смене устройства не открывается второй порт, если прежний не удалось закрыть.

В React подписки `midi:state` и `midi:note` создаются один раз и снимаются при размонтировании. Обработчик получает актуальные настройки и вызывает существующий `noteOn` с `source: "midi"`. Проверка высоты, счётчики, задержки и генерация не дублируются. Параметры тренировки и физический диапазон инструмента не калибруются.

Выбор хранится отдельно в `sonari.midi.input.v1`. Для сопоставления используются точные WinMM-имя, manufacturer ID, product ID и версия драйвера; индекс порта не считается постоянной идентичностью. Два одинаковых совпадения запрещают автоматическое подключение.

## Ограничения

- WinMM не предоставляет надёжное уведомление о каждом физическом отключении. Используются повторное перечисление устройств, проверка capabilities открытого handle, сообщения закрытия и ошибки API. Если драйвер сохраняет отключённый порт в списке без сообщения об ошибке, выберите виртуальный ввод и подключитесь повторно вручную. После обнаруженной потери соединения Find a Note повторяет подключение раз в 2 секунды при единственном точном совпадении. Выбор виртуального ввода отменяет эти попытки.
- WinMM-идентичность не содержит серийного номера. При замене инструмента идентичной моделью единственное точное совпадение считается ранее выбранным входом; при нескольких одинаковых портах требуется ручной выбор.
- Зависание неисправного стороннего драйвера внутри системного WinMM-вызова не может быть отменено этим API. MIDI работает вне UI-потока; при обычном отключении обработчик закрывает порт и сохраняет виртуальный ввод.
- Принимаются Note On/Off всех 16 каналов; SysEx, звук, sustain-озвучивание и MIDI Output не реализуются. Контроллеры All Notes Off / All Sound Off очищают удерживаемые ноты соответствующего канала.
- Windows 10 и другие масштабы DPI требуют отдельной аппаратной проверки. Тесты с искусственными сообщениями не доказывают работу конкретного USB-драйвера.

Системные API: [перечисление и capabilities](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/nf-mmeapi-midiingetdevcapsw), [открытие MIDI-входа](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/nf-mmeapi-midiinopen), [закрытие](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/nf-mmeapi-midiinclose).

## Подтверждённая аппаратная проверка

Yamaha P-45 проверена пользователем в реальном Windows EXE. Windows предоставляет её как `Digital Piano`. Подтверждены физические нажатия, обнаружение отключения USB и автоматическое переподключение после возвращения инструмента. Реальные снимки находятся в `screenshots/midi-01/`; диагностика на снимке `midi-note-yamaha.jpg` показывает A3, MIDI 57, канал 1, velocity 50.

Полностью пустой список MIDI-входов проверен автоматическим UI-тестом. На компьютере также доступны порты SE25, поэтому реальный снимок `virtual-input.jpg` показывает виртуальный ввод без активного MIDI-соединения, а не полное отсутствие аппаратных входов.
