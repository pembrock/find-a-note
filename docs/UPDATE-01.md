# UPDATE-01 · обновления Find a Note

## Источник и интерфейс

Updater находится в `internal/update`. `UpdateProvider` сообщает версию и доступные файлы. GitHub-провайдер использует `GET /repos/pembrock/find-a-note/releases/latest` для стабильного релиза и скачивает его assets по адресу с проверенным тегом и именем файла. Черновики, prerelease, текущая версия и downgrade не предлагаются. Версии из `wails.json` сравниваются как три целых числа от 0 до 65535, в порядке MAJOR, MINOR, PATCH.

`Launcher` выбирает пакет для платформы и запускает установку. Windows-реализация различает per-user NSIS и Portable по пути работающего EXE и записи Windows. Будущая macOS-реализация сможет использовать тот же provider, manifest и интерфейс, добавив выбор пакета, проверку подписи macOS и свой транзакционный способ установки.

Production-приложение проверяет обновления асинхронно при запуске. Проверка ограничена 25 секундами, загрузка пакета — пятью минутами. DNS, ошибки HTTP и лимиты GitHub видны как общий сбой только при ручной проверке. Доступная версия обозначается кнопкой в заголовке, а действия находятся в «О программе». «Позже» сохраняет выбор для этой версии. Проверенную загрузку можно отменить или установить после отдельного подтверждения перезапуска.

## Подпись и manifest

Каждый поддерживаемый выпуск содержит `update-manifest.json` и `update-manifest.sig`. JSON в UTF-8, без BOM, пробелов между полями и завершающего перевода строки. Точные байты задаёт `CanonicalManifest`: `encoding/json.Marshal` с фиксированными структурами, порядком полей и стандартным экранированием Go. При чтении проверяются подпись исходных байтов и побайтное равенство каноническому JSON. Дубликаты и неизвестные поля отвергаются. Подпись — 64 байта Ed25519 без текстовой обёртки.

- Заголовок содержит `schema: 1`, `product: "find-a-note"`, `version`, `notes` и `packages`. Версия должна совпадать с GitHub-тегом `vMAJOR.MINOR.PATCH`. Описание отображается как текст.
- Каждый пакет содержит `os`, `arch`, `kind`, `name`, `size`, `sha256` и `method`. Размер указан в байтах, SHA-256 — 64 строчными hex-символами. Для Windows допускаются `windows/amd64`, `portable/replace-exe` и `installer/nsis-stage-v1` с именами стандартных артефактов.
- Подписанный Portable также задаёт контрольную сумму EXE, извлекаемого из Setup в режиме обновления. Setup и Portable собираются из одного EXE.
- HTTPS, ограниченные редиректы GitHub, сверка размера и SHA-256 защищают транспорт и содержимое. Авторство устанавливает Ed25519 с открытым ключом, встроенным в приложение. SHA-256 отпечаток 32 байтов открытого ключа в hex — `86a0fddb3a48dff12a62bea92e1efe46d8a97bdf7a0921f47aa827e8be9f11bb`.

Закрытый ключ хранится вне репозитория, в отдельном файле PKCS#8 PEM с ACL текущего владельца. Храните резервную копию под шифрованием и открывайте ключ только при подписании выпуска. Потеря ключа требует ручной установки сборки с новым открытым ключом. Процедуры удалённой ротации и отзыва на этом этапе нет.

## Установка, перезапуск и восстановление

После подтверждения текущий EXE копируется как helper в соседний каталог с ACL текущего пользователя. Helper сверяет подпись, версию, тип и байты пакета повторно, делает резервную копию и открывает handle родительского процесса. Приложение завершает работу только после подтверждения подготовки, а helper ждёт освобождения старого EXE.

- **Portable.** Новый проверенный EXE атомарно подменяет старый на том же томе. Для защищённых каталогов операция завершается ошибкой подготовки, без UAC.
- **Установленная версия.** Helper запускает подтверждённый NSIS в тихом режиме `/UPDATESTAGE`. NSIS извлекает приложение в изолированный каталог по маркеру и не изменяет пользовательский профиль или ярлыки. Helper сверяет извлечённый EXE с подписанным Portable, подменяет установленный EXE и после успешного запуска обновляет `DisplayVersion`. Существующий деинсталлятор продолжает удалять приложение с того же пути.
- **Откат.** Новая программа подтверждает запуск после монтирования React. При ошибке подмены, преждевременном выходе или отсутствии подтверждения helper оставляет или восстанавливает исходный EXE и запускает его с уведомлением об откате. После успеха рабочий каталог убирается. Если система не даёт восстановить файл, helper показывает путь к оставленной резервной копии `previous.exe`. Для ручного восстановления закройте работающие копии Find a Note и верните эту копию на исходное место.

Оба варианта продолжают пользоваться `%APPDATA%\Sonari.exe` и прежним origin WebView2. Updater не переносит, не копирует в релиз и не удаляет настройки.

## Как подготовить следующий выпуск

1. В чистой ветке выпуска установите следующую версию в `wails.json → info.productVersion`. Подготовьте краткое текстовое описание обновления в UTF-8. Проверьте изменения и зафиксируйте исходники.
2. Соберите и подпишите артефакты на машине, имеющей доступ к закрытому ключу. Передавайте путь к ключу локально, без копирования ключа в каталог сборки.

   ```powershell
   $signingKey = Join-Path $env:LOCALAPPDATA 'Find-a-Note-Signing\update-ed25519.pem'
   ./scripts/build-release.ps1 -SigningKey $signingKey -UpdateNotes ./release-summary.txt
   ```

3. Проверьте обе сборки и их metadata. С `-SigningKey` сценарий добавляет `update-manifest.json` и `update-manifest.sig` к Setup, Portable и `SHA256SUMS.txt`. Редактирование manifest после подписания делает подпись недействительной.
4. После отдельного разрешения на публикацию приложите пять файлов к стабильному GitHub Release с тегом версии из manifest и предоставьте соответствующие исходники. Скачайте assets, сверяйте подпись и SHA-256 до перевода черновика в стабильный выпуск.

Публичный v0.1.0 выпущен до появления updater. Для подключения обновлений пользователю потребуется один раз вручную установить будущую сборку с этим открытым ключом.

## Результаты проверки

Проверено на Windows 11 x64 с WebView2, Go 1.27.4, Node.js 24.16.0, Wails 2.17.0 и NSIS 3.12. Для сквозных тестов собраны две отдельные Wails-версии с updater, 0.1.0 и 0.1.1. Они используют loopback-провайдер, временную пару Ed25519, синтетический профиль WebView2, отдельную папку установки и отдельную запись реестра.

| Проверка | Результат |
| --- | --- |
| Frontend build, модульные тесты | PASS, 9 тестов. |
| Playwright | PASS, 37 тестов. Проверены настройки, MIDI и аудио, а также отложенное уведомление, прогресс, отмена, повтор загрузки и отдельное подтверждение установки. |
| Go tests и vet | PASS. Проверены сравнение версий, отсутствие релиза, сеть и HTTP-ошибки, чужая архитектура, неподходящие файлы, некорректный JSON, неверная подпись, повреждение, обрыв, отмена, повтор и запрет установки без проверенного скачивания. Общий модуль компилируется для Darwin arm64. |
| Windows production и NSIS | PASS, собраны Setup, Portable и SHA-256. Инструмент подписания проверен временным ключом на тестовых EXE. |

| Реальный откат Portable и Installer | PASS, тестовый 0.1.1 завершался до подтверждения запуска. Helper вернул и запустил EXE 0.1.0 в обоих сценариях. |
| Настройки после обновления и отката | PASS во всех четырёх сценариях. Сверены семь записей синтетического профиля, включая тренировку, диапазон, отображение, звук и громкость, настройки MIDI-входа и калибровку. |
