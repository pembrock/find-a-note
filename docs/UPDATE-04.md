# UPDATE-04 · Find a Note 0.2.2

## Диалог обновления

Индикатор в верхней панели открывает отдельный диалог. Через «Настройки → О программе → Проверить обновления» открывается тот же диалог и запускается ручная проверка. Если проверка уже идёт, диалог показывает её текущее состояние. Если пакет подготовлен, диалог предлагает продолжить установку.

| Состояние | Поведение |
| --- | --- |
| Проверка | Показывает ход проверки, затем сообщает о текущей версии, доступном обновлении или ошибке. |
| Доступно | Показывает новую и установленную версии. Заметки отображаются обычным текстом в прокручиваемой области. «Позже» закрывает окно, индикатор остаётся доступным. |
| Загрузка | Показывает записанные байты и процент от размера подписанного пакета. При неизвестном размере отображается неопределённый прогресс без процента. «Отмена» останавливает загрузку и возвращает предложение. Escape закрывает окно после остановки. |
| Готово | Пакет уже проверен. «Позже» оставляет его готовым до завершения приложения. «Перезапустить» открывает подтверждение, после которого запускается установка. |
| Подготовка перезапуска | Закрытие диалога и штатное закрытие окна заблокированы, пока helper подтверждает готовность. После подтверждения приложение завершает работу, чтобы helper заменил файлы. |
| Ошибка | Короткое сообщение и повтор соответствующего действия. Отдельные сообщения используются для недоступности источника, ошибки проверки manifest или пакета, нехватки места или прав и ошибки подготовки замены. |

Диалог использует нативный HTML-элемент dialog в WebView2. Tab переключает элементы внутри окна, Enter активирует сфокусированную кнопку, Escape закрывает диалог до критической стадии. После закрытия фокус возвращается на элемент, открывший окно.

## Фоновая проверка и перезапуск

Go запускает проверку сразу, затем раз в 60 минут. Состояние сервиса объединяет ручную и автоматическую проверки без параллельных запросов. Проверка пропускается во время загрузки, при готовом пакете и при подготовке установки. Фоновый сбой не открывает окно, а ранее проверенное предложение остаётся доступным при временной ошибке. Следующая проверка выполняется по расписанию. Закрытие приложения отменяет контекст сетевых операций.

React читает состояние и фактические счётчики через Wails Status, который использовался в предыдущей версии. При открытом диалоге состояние обновляется чаще. GitHub UpdateProvider, подписанный формат manifest, Ed25519, проверка размера и SHA-256, NSIS/Portable, замена файлов и rollback используют существующий механизм.

Новое приложение отправляет helper сигнал готовности WebView и ожидает существующий маркер завершения. Helper записывает маркер после подтверждения запуска и, для установленной версии, обновления регистрации Windows. Только процесс, запущенный в режиме подтверждения обновления, получает одноразовое сообщение об успехе. Для восстановления предусмотрено отдельное сообщение. При обычном запуске уведомление отсутствует.

## Проверки и артефакты

- Frontend production build и 9 модульных тестов прошли.
- Playwright прошёл 49 тестов. Проверены диалог, ручная проверка, прогресс с известным и неизвестным размером, отмена, повтор, отложенный перезапуск, уведомления, клавиатурная навигация и длинные заметки при 760×560, 900×600 и 1920×1032.
- Регрессионные сценарии Playwright покрыли MIDI, Web Audio, тренировки, калибровку и сохранение настроек. Использованы эмулированные MIDI-события.
- Go test и Go vet прошли. В тесте планировщика часы заменены управляемыми тиками. Проверены стартовый и следующий запросы, восстановление после ошибки, отсутствие параллельной проверки и блокировка проверок на стадиях загрузки и готовности.
- Собраны Windows x64 production, NSIS Setup и Portable в `artifacts/windows-0.2.2`. Там же находятся `SHA256SUMS.txt`, `update-manifest.json` и `update-manifest.sig`.
- OpenSSL подтвердил Ed25519-подпись. SHA-256 отпечаток 32 байтов открытого ключа — `86a0fddb3a48dff12a62bea92e1efe46d8a97bdf7a0921f47aa827e8be9f11bb`. Сверены оба пакета и 39 встроенных ресурсов, включая 30 аудиосэмплов.
- Скриншоты Playwright находятся в `artifacts/update-04-screenshots`. На них 0.2.2 уже запущена, а 0.2.3 используется как тестовое предложение.

## Изолированное обновление и откат

Исходный код публичной 0.2.1 собран отдельно с локальным источником обновлений и тестовой регистрацией Installer. Локальный сервер отдавал подписанные production-пакеты 0.2.2. Тестовый код подтверждал перезапуск через backend после загрузки и проверки. Само подтверждение через интерфейс проверено Playwright.

| Сценарий | Проверка |
| --- | --- |
| Portable, обычный запуск новой версии | EXE совпал по SHA-256 с Portable 0.2.2. Новый WebView подтвердил готовность, временный каталог helper очищен. |
| Installer, обычный запуск новой версии | EXE совпал с Portable 0.2.2. Версия в отдельной записи Windows стала 0.2.2. Ярлык сохранился. |
| Portable, ошибка запуска после замены | Helper восстановил EXE 0.2.1 и запустил его в режиме восстановления. |
| Installer, ошибка запуска после замены | Helper восстановил EXE 0.2.1 и запустил его в режиме восстановления. Тестовая запись Windows сохранила версию 0.2.1 и ярлык. |

Во всех случаях после завершения проверены семь записей отдельного профиля. Среди них настройки тренировки и диапазона, настройки интерфейса, звук, выбранный MIDI-вход и профиль калибровки. Ошибка запуска для сценариев rollback внесена в тестовый helper после подмены EXE. Нативный прогон проверяет результат обновления по хешам, маркерам и перезапуску, а отображение и закрытие сообщения об успехе проверены в Playwright.

## Ограничения

Подготовленный пакет сохраняется в текущем процессе. После выхода из приложения загрузку потребуется повторить. Физический контроллер и отключение питания во время замены не проверялись. Сборка предназначена для ручной проверки перед публикацией.
